# تطبيق متابعة حضور الطلاب في الصلوات الخمس

تطبيق جوّال يعمل على **أندرويد وآيفون**، بالعربية واتجاه RTL، ويحفظ جميع البيانات **على الهاتف فقط** دون الحاجة إلى إنترنت.

---

## 1. تحليل الفكرة

الهدف الأساسي: بعد الصلاة مباشرة يفتح المشرف التطبيق، فيجد **الصلاة الحالية والتاريخ محدّدين تلقائيًا**، يختار الصف، يضغط «تحديد الباقين حاضرين»، ثم يلمس المتغيبين فقط. العملية لصف من 30 طالبًا تستغرق أقل من دقيقة.

قرارات التصميم المهمة:

| المتطلب | الحل |
|---|---|
| سرعة التسجيل | شاشة واحدة فيها التاريخ والصلاة والصف والقائمة معًا، بلا تنقّل بين صفحات. الحفظ تلقائي مع كل لمسة. |
| تخمين الصلاة | يُختار تلقائيًا حسب الوقت (الفجر قبل 10 ص، الظهر قبل 3 م، العصر قبل 5:45 م، المغرب قبل 7:15 م، ثم العشاء). |
| الانتقال السريع | أزرار الصلوات الخمس دائمًا ظاهرة، ونقطة خضراء على الصلاة المكتملة، وبعد إكمال صف يظهر زر «الصف التالي». |
| دقة الإحصائيات | الصلاة التي لم تُسجَّل لا تُحسب غيابًا. النسبة = الحضور ÷ (الحضور + الغياب) للسجلات الفعلية فقط. |
| نقل طالب بين الصفوف | كل سجل حضور يحفظ صف الطالب **وقت التسجيل**، فلا تتغيّر التقارير القديمة عند نقله. |
| الغياب بعذر | يُحسب غيابًا في العدد، ويظهر منفصلًا «بعذر» في كل التقارير. |
| حذف الطالب | يوجد «أرشفة» (يختفي من التسجيل ويبقى سجله في التقارير) و«حذف نهائي». |

## 2. التقنيات المختارة

| الطبقة | التقنية | السبب |
|---|---|---|
| الواجهة | React 18 + TypeScript + Vite | واجهة واحدة لأندرويد وآيفون، دعم ممتاز للعربية وRTL. |
| التطبيق الأصلي | Capacitor 7 | يغلّف الواجهة في تطبيق أندرويد (APK) وتطبيق iOS حقيقيين، مع الوصول للملفات والمشاركة وزر الرجوع. |
| قاعدة البيانات | IndexedDB عبر Dexie.js | قاعدة بيانات محلية داخل التطبيق، سريعة، مفهرسة، وتعمل دون إنترنت. |
| Excel | SheetJS (xlsx) | استيراد الطلاب وتصدير التقارير بأوراق متعددة واتجاه يمين لليسار. |
| PDF | html2canvas + jsPDF | يرسم العربية بشكل صحيح (تشكيل الحروف واتصالها) بخط Tajawal المضمَّن في التطبيق. |
| الخط | Tajawal (مضمّن) | يعمل دون إنترنت. |

## 4. قاعدة البيانات

```
classes      (id, name, order, createdAt, updatedAt)
students     (id, name, classId, serial, phone?, active, createdAt, updatedAt)
attendance   (id = "التاريخ|الصلاة|الطالب", date, prayer, studentId, classId,
              status: P|A, excused?, note?, updatedAt, by)
users        (id, name, role: admin|supervisor, pinHash, perms, active)
settings     (key, value)      — اسم الجهة، تاريخ آخر نسخة احتياطية…
```

- معرّف سجل الحضور مركّب من (التاريخ + الصلاة + الطالب)، فلا يمكن أن يتكرر سجل الطالب في نفس الصلاة.
- فهارس: `date` و`[date+prayer]` و`[date+prayer+classId]` و`[studentId+date]` لسرعة اللوحة وسجل الطالب.
- رمز الدخول محفوظ مُشفَّرًا (SHA-256) وليس نصًا صريحًا.

صلاحيات المشرف (يحددها المسؤول لكل مشرف):
- الصفوف المسموحة (كلها أو صفوف محددة)
- مراجعة التقارير
- تصدير التقارير
- تعديل حضور الأيام السابقة (بدونها يستطيع التسجيل لليوم فقط)

## 5. التشغيل والبناء

```bash
npm install
npm run dev          # تجربة في المتصفح
npm run build        # بناء الواجهة
npx cap sync         # نسخ الواجهة إلى مشروعي أندرويد وiOS
```

### أندرويد (APK)
- **عبر Android Studio:** افتح مجلد `android` ثم Build › Build APK(s).
- **من سطر الأوامر:** `cd android && ./gradlew assembleDebug` ← الملف في `android/app/build/outputs/apk/debug/app-debug.apk`
- **عبر GitHub:** ارفع المشروع إلى مستودع على GitHub، وسيبني ملف `.github/workflows/android.yml` ملف APK تلقائيًا (تجده في تبويب Actions › Artifacts).

### آيفون (iOS)
يتطلب جهاز Mac عليه Xcode:
```bash
npm install && npm run build && npx cap sync ios
npx cap open ios     # يفتح Xcode
```
ثم اختر فريق التوقيع (Apple ID) وشغّل على الآيفون مباشرة، أو انشره عبر TestFlight / App Store.

## 6. النسخ الاحتياطي
البيانات على الهاتف فقط. من «المزيد ← حفظ نسخة احتياطية» يُصدَّر ملف JSON يمكن حفظه أو إرساله (واتساب، بريد، Drive)، ومن «استرجاع» تُستعاد البيانات على أي جهاز آخر (أندرويد أو آيفون).

## 7. قابلية التوسع
- إضافة حقول جديدة للطالب أو حالات حضور جديدة (مثل «متأخر») تتم بإصدار جديد من قاعدة البيانات في `schema.ts` دون فقدان البيانات.
- كل جدول فيه `updatedAt` ومعرّفات UUID، فإضافة مزامنة سحابية لاحقًا ممكنة دون تغيير البنية.
- كل التقارير تُبنى من `stats.ts` و`reportDoc.ts`، فإضافة تقرير جديد لا تتطلب إلا دالة واحدة، ويظهر تلقائيًا على الشاشة وفي Excel وPDF.

## 8. المزامنة بين الأجهزة (اختيارية)
تعمل عبر Firebase Firestore (خطة مجانية). الإعدادات في `src/firebaseConfig.ts`.

- الواجهة تقرأ دائمًا من قاعدة البيانات المحلية، فيبقى التطبيق سريعًا ويعمل دون إنترنت.
- كل تعديل محلي يُسجَّل تلقائيًا في جدول `outbox` ويُرفع عند توفر الاتصال (`src/sync/sync.ts`).
- تغييرات الأجهزة الأخرى تصل لحظيًا وتُكتب محليًا. عند تعديل نفس السجل من جهازين يُعتمد الأحدث.
- المسؤول يفعّل المزامنة من «المزيد» فيحصل على رمز المدرسة، والمشرف يدخل الرمز عند أول تشغيل.
- البنية: `schools/{رمز المدرسة}/{classes|students|attendance|users|settings}/{id}`.

قواعد Firestore المطلوبة:
```
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    match /schools/{school}/{coll}/{doc} {
      allow read, write: if request.auth != null;
    }
  }
}
```
ويجب تفعيل Anonymous في Authentication.

## 9. اللغات والأنشطة الإضافية
- التطبيق بلغتين: **التركية (الافتراضية)** والعربية. التبديل من شاشة الدخول أو «المزيد ← Dil / اللغة». تتغير اتجاهات الواجهة (LTR/RTL) والتقارير وملفات PDF/Excel حسب اللغة.
- **الأنشطة**: تحضير لموضوعات غير الصلاة (يبدأ بـ «التواجد في الكلية / Kolejde Bulunma»). يُسجَّل مرة واحدة يوميًا لكل نشاط، وإحصاءاته منفصلة عن الصلوات. يضيف المسؤول أنشطة أخرى أو يعدّلها من «الطلاب ← الأنشطة».
- سجلات النشاط تُخزَّن في جدول الحضور نفسه بالمعرّف `a:<id>` مكان اسم الصلاة، فتشملها النسخة الاحتياطية والمزامنة تلقائيًا.
