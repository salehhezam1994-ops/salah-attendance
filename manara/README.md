# منارة المعرفة — المرافق المعرفي الذكي

تطبيق يبني مع المستخدم معرفة عميقة ومتراكمة في أي موضوع: يقابله بحوار طبيعي، ويفهم هدفه، ويبحث في المصادر الموثوقة، ويبني له خطة وخريطة معرفية، ويقدم له جرعة يومية موثقة بخمسة مستويات عمق، ويناقشه ويراجع معه ويربط ما تعلمه بما سبق.

> المشروع مستقل داخل المجلد `manara/` ولا يمس تطبيق «متابعة الصلاة» الموجود في جذر المستودع.

---

## 1. التشغيل

```bash
cd manara
npm install
cp .env.example .env        # ضع ANTHROPIC_API_KEY للتشغيل الفعلي
npm run build               # يبني الواجهة إلى dist/
npm start                   # الخادم + الواجهة على http://localhost:8787
```

للتطوير: `npm run dev:server` و `npm run dev:web` (الواجهة على 5173 وتمرر `/api` إلى الخادم).

| الوضع | كيف | ماذا يحدث |
|---|---|---|
| فعلي | `ANTHROPIC_API_KEY=...` | مقابلة ذكية، بحث حي في المصادر، خطط ومواد موثقة، مرافق حواري، متابعة المستجدات. |
| تجريبي معلن | `MANARA_AI=demo` | لتجربة الواجهة بلا مفتاح: خطط ومواد **عامة بلا مصادر**، وتظهر لافتة «وضع تجريبي» في كل مكان. |
| بلا ذكاء اصطناعي | بلا مفتاح | المقابلة تعمل (محرك قواعد)، والقراءة والمراجعة والملاحظات تعمل لما أُعد سابقًا؛ إعداد الخطط والمواد يعرض رسالة واضحة. |

الاختبارات: `npm test` (وحدات + اختبار تكامل كامل للواجهة البرمجية بقاعدة بيانات في الذاكرة).

### النشر بنقرة (Render)
ملف `render.yaml` في جذر المستودع يُعدّ كل شيء: البناء، والتشغيل، وقرص دائم للبيانات، وفحص الصحة.
1. افتح: https://render.com/deploy?repo=https://github.com/salehhezam1994-ops/salah-attendance واختر الفرع الذي فيه المشروع.
2. أدخل `ANTHROPIC_API_KEY` حين يُطلب (يبقى في Render ولا يُحفظ في المستودع).
3. افتح الرابط الناتج على الهاتف ← «إضافة إلى الشاشة الرئيسية». ولبناء APK يفتح الخادم: ضع الرابط في متغير المستودع `MANARA_SERVER_URL` وأعد تشغيل سير العمل «Manara — Android APK».

الخطة `starter` مدفوعة لأن القرص الدائم غير متاح في الخطة المجانية؛ بدونه تُفقد الحسابات عند كل إعادة تشغيل.

## 2. القرارات المعمارية

| الطبقة | الاختيار | السبب |
|---|---|---|
| الواجهة | React 18 + TypeScript + Vite، PWA | نفس تقنيات المستودع؛ واجهة واحدة للهاتف والجهاز اللوحي والويب، وقابلة للتغليف بـ Capacitor كما في التطبيق الحالي. RTL/LTR كامل. |
| الخادم | Node 22 + Hono | خفيف ومكتوب بـ TypeScript. **مفتاح الذكاء الاصطناعي على الخادم فقط.** |
| قاعدة البيانات | SQLite عبر `node:sqlite` | علائقية مع مفاتيح خارجية وحذف متتابع، دون اعتماديات أصلية. يمكن نقلها إلى PostgreSQL لاحقًا لأن الوصول محصور في `server/db.ts`. |
| الذكاء الاصطناعي | Claude عبر `@anthropic-ai/sdk` | مخرجات منظمة (JSON schema) لكل وكيل، وبحث ويب من جهة الخادم مع استشهادات حرفية. نموذج قوي للتخطيط والتركيب، وأخف للمقابلة والمراجعة (`MANARA_MODEL_STRONG/FAST`). |
| الحسابات | جلسة HttpOnly + scrypt | يبدأ المستخدم فورًا كضيف (بلا نماذج)، ثم يحوّله إلى حساب دون فقد بياناته. |

### وحدات الذكاء الاصطناعي (`server/ai/`)
لا يوجد prompt واحد ضخم؛ لكل وحدة مدخلات ومخرجات محددة بمخطط:

| الوحدة | الملف | الدور |
|---|---|---|
| Interview Agent | `interview.ts` | محرك خانات حتمي يحدد ما الناقص (يعمل دون ذكاء اصطناعي)، والنموذج يفهم الإجابات الحرة ويملأ عدة خانات ويطلب التوضيح ويصوغ السؤال التالي. سؤال واحد في كل مرة، مع «لم أفهم السؤال» و«السؤال السابق». |
| Goal Analysis | `planner.ts` | يعيد صياغة الهدف («فهمت أنك تريد…») ويحدد طبيعة المجال ونموذج الخريطة. يعدّله المستخدم بلغته. |
| Research Agent | `research.ts` | بحث ويب عبر Claude + محولات OpenAlex وCrossref وWikipedia وOpen Library. |
| Source Verification | `verify.ts` | DOI عبر Crossref، والوصول للرابط، وتصنيف: موثّق / من نتائج بحث حي / غير متحقق / تعذر الوصول. |
| Curriculum Planner | `planner.ts` | مراحل، وعقد شجرة (جذور/جذع/فروع/أوراق)، وعلاقات مصنفة، واستعلامات بحث لكل عقدة، مبنية على ملاحظات البحث. |
| Synthesis Agent | `synthesis.ts` | المادة اليومية بخمسة مستويات + المفاهيم + أسئلة المراجعة. |
| Citation Module | `verify.ts` | يفرض قواعد الأمانة على النص المولد (انظر 3). |
| Tutor / Review / Progress | `tutor.ts`، `review.ts` | مناقشة سياقية، جدولة مراجعة متباعدة، ملخص تراكمي. |

## 3. الأمانة العلمية: كيف يُمنع الاختلاق
1. **لا يدخل مصدر إلا من نتيجة بحث حقيقية.** يستطيع النموذج وصف المصدر وتصنيفه، لكن أي رابط لم يرد في نتائج البحث يُرفض.
2. **المقتطفات حرفية:** نص `cited_text` الذي يعيده محرك البحث، أو الملخصات من قواعد البيانات. هذه وحدها قابلة للاقتباس.
3. **كل ادعاء يشير إلى مقتطفات (E-ids).** وحدة الاستشهاد:
   - تحذف أي إحالة إلى مقتطف غير موجود.
   - تعلّم الحقيقة أو الرأي المنسوب لشخص دون إحالة صالحة بأنه **«غير موثّق»** وتظهره للمستخدم بتنبيه (أو تخفيه في المعيار الصارم).
   - تحذف أي اقتباس لا يوجد حرفيًا في مقتطفه.
4. يميز النص بين **حقيقة / استنتاج / رأي** ومستوى اليقين، ويعرض الأقوال مع أصحابها وقوة أدلتها، ويصرح بحدود المعرفة المتاحة.
5. أرقام الصفحات والمواضع لا تُعرض إلا إذا وردت في المقتطف.
6. إذا لم توجد مقتطفات كافية، لا تُكتب المادة («لم أعثر على مصادر كافية… ولن أكتبها دون توثيق»).
7. لكل مادة «تقرير توثيق»: عدد الادعاءات الموثقة وغير الموثقة والاستنتاجات المعلنة والاقتباسات المحذوفة.

تغطي الاختبارات (`tests/`) رفض المصادر المختلقة، وحذف الإحالات والاقتباسات غير الصحيحة، وعزل بيانات المستخدمين.

## 4. ما تم تنفيذه
**المرحلة الأولى (الأساس):** الهوية والتصميم (عربي/إنجليزي، فاتح/داكن)، الدخول كضيف وإنشاء حساب، المقابلة المعرفية الحوارية، تأكيد الهدف وتعديله، الخطة المقترحة والموافقة قبل البدء، الصفحة الرئيسية، المادة اليومية، زر «المزيد» بخمسة مستويات وزمن كل مستوى، المصادر والتوثيق، حفظ التقدم، التفضيلات، تعديل الخطة باللغة الطبيعية (مع طلب تأكيد للتغييرات الكبيرة، ودون المساس بما دُرس).

**المرحلة الثانية (المعرفة المتراكمة):** الخريطة المعرفية التفاعلية (شجرة تنمو من الجذور، ثمار للمتقن، تكبير/تصغير، سحب، طي/توسيع، بحث، علاقات مصنفة، عرض الكل، نسبة إنجاز لكل عقدة)، المكتبة الشخصية (المحفوظة، المقروءة، المفاهيم، الملاحظات، المصادر، البحث والتصفية)، المراجعة المتباعدة والاختبارات القصيرة، المرافق الحواري السياقي، الملخص التراكمي، صفحة التقدم.

**المرحلة الثالثة (جزئيًا):**
- الصوت: الاستماع للمادة (تشغيل/إيقاف/إعادة الجملة/السرعة/الخلاصة أو الكل) والإملاء والأوامر الصوتية («أين وصلنا؟»، «اختبر فهمي»، «احفظ ملاحظة: …»، «المادة التالية»…)، عبر قدرات المتصفح.
- النافذة العائمة: Document Picture-in-Picture (نافذة صغيرة فوق التطبيقات على أجهزة سطح المكتب بمتصفحات Chromium)، مع نافذة منبثقة بديلة، و«المشاركة إلى منارة» (Web Share Target) لإرسال نص أو رابط من تطبيق آخر إلى المرافق.
- متابعة المستجدات مع التصنيف (مهم/عادي/رأي/غير مؤكد/أولي)، ولا يُضاف شيء للخطة إلا بموافقة.
- التنبيهات المحلية (وقت الجرعة، المراجعة) بإذن المستخدم.
- بنية الاشتراكات والحدود الشهرية (دون أسعار) ولوحة إحصاءات للمشرفين (`/api/admin/stats`).
- العمل دون اتصال للمواد التي فُتحت سابقًا (Service Worker).

## 4.1 التنبيهات من الخادم
- **قناتان:** Web Push (VAPID) للمتصفح والتطبيق المثبت، و Firebase Cloud Messaging (HTTP v1) لتطبيق أندرويد الأصلي. مفاتيح VAPID تُولَّد تلقائيًا وتُحفظ في `DATA_DIR/vapid.json` إن لم تُحدد في البيئة.
- **المجدول** (`server/services/notifier.ts`) يعمل كل دقيقة وبتوقيت المستخدم المحلي (تُرسل المنطقة الزمنية من الجهاز):
  - تذكير واحد في اليوم على الأكثر: جرعة اليوم (مع عدد المراجعات)، أو المراجعة إن كانت الجرعة مقروءة.
  - لا شيء في ساعات الهدوء (افتراضيًا 22:00–07:00، قابلة للتعديل).
  - بعد غياب 3 أيام يتوقف التذكير اليومي، وتصل رسالة «مرحبًا بعودتك» في اليوم الثالث والسابع فقط ثم صمت.
  - تُحضَّر مادة اليوم قبل موعدها بـ45 دقيقة لتكون جاهزة عند وصول التنبيه.
  - متابعة المستجدات أسبوعيًا تلقائيًا لمن فعّلها وباقته تشملها، مع تنبيه واحد عند وجود جديد.
- الاشتراكات الميتة (410/404 أو UNREGISTERED) تُحذف تلقائيًا. زر «أرسل تنبيهًا تجريبيًا» في التفضيلات.
- على آيفون: Web Push يعمل فقط بعد إضافة التطبيق إلى الشاشة الرئيسية؛ وإلا يبقى التذكير المحلي أثناء فتح التطبيق.
- لتطبيق أندرويد: ضع `google-services.json` (سر المستودع `GOOGLE_SERVICES_JSON` في CI) وحساب الخدمة في `FCM_SERVICE_ACCOUNT` على الخادم. بدونهما لا يُعرض خيار التنبيهات الأصلية بدل أن يفشل.

## 4.2 تطبيق أندرويد والنافذة العائمة
- `android/` غلاف Capacitor يحمّل الخادم المنشور (`MANARA_SERVER_URL`)، فتشترك الصفحات والجلسة والنافذة العائمة في الأصل نفسه:
  ```bash
  MANARA_SERVER_URL=https://manara.example.com npx cap sync android
  cd android && ./gradlew assembleDebug
  ```
  ويبنيه سير العمل `.github/workflows/manara-android.yml` تلقائيًا مع الاختبارات و lint (متغير المستودع `MANARA_SERVER_URL`).
- **النافذة العائمة** (`FloatingCompanionPlugin` + `FloatingService`):
  - يشرح التطبيق الإذن أولًا ثم يفتح صفحة إعداد «الظهور فوق التطبيقات الأخرى» ليمنحه المستخدم بنفسه.
  - فقاعة صغيرة قابلة للسحب تلتصق بالحافة؛ اللمس يفتح لوحة قابلة للتحريك من شريطها وتغيير الحجم من مقبضها (ضمن حدود الشاشة، ويُحفظ الموضع والحجم).
  - اللمس خارج اللوحة يعيد لوحة المفاتيح للتطبيق الذي تحتها؛ التصغير يوقف الـ WebView لتوفير الموارد.
  - خدمة أمامية بإشعار ظاهر فيه زر «إغلاق». لا تفتح إلا صفحات منارة؛ الروابط الخارجية (كالمصادر) تفتح في المتصفح.
  - **لا تقرأ الشاشة ولا محتوى التطبيقات الأخرى.** يصلها النص فقط حين يختار المستخدم «اسأل منارة» من قائمة تحديد النص (ACTION_PROCESS_TEXT) أو «مشاركة».
- النشر على Google Play: إذن `SYSTEM_ALERT_WINDOW` ونوع الخدمة `specialUse` يتطلبان تبريرًا في نموذج المراجعة (الوصف موجود في `AndroidManifest.xml`).

## 5. قيود صريحة وما بقي
- **لم يُختبر الاتصال الحي بـ Claude في بيئة التطوير هذه** (لا يوجد مفتاح). المسار مختبر بمزود وهمي داخل الاختبارات فقط، والواجهة مختبرة في الوضع التجريبي المعلن.
- **قواعد البيانات الأكاديمية** (OpenAlex/Crossref/Wikipedia/Open Library) كانت محجوبة في شبكة بيئة التطوير؛ الكود يتحمل فشلها ويعتمد حينها على بحث Claude وحده.
- **النافذة العائمة على أندرويد** مبنية (انظر 4.2) لكنها **لم تُجرَّب على جهاز حقيقي** في هذه البيئة؛ التحقق الحالي هو بناء APK و lint في CI. على iOS لا يسمح النظام بنوافذ فوق التطبيقات؛ البديل المشاركة إلى التطبيق.
- الإملاء الصوتي داخل تطبيق أندرويد والنافذة العائمة غير متاح (WebView لا يدعم Web Speech API)؛ الكتابة تعمل. يحتاج إضافة أصلية للتعرف على الكلام.
- **التنبيهات**: Web Push مختبر بطلب مشفّر حقيقي إلى خادم محلي، و FCM مختبر بتوقيع JWT وشكل الرسالة مع اعتراض الشبكة — لم يُرسل تنبيه فعلي إلى جهاز لعدم توفر مشروع Firebase.
- أيقونات تطبيق أندرويد هي الافتراضية من Capacitor وتحتاج استبدالًا بهوية منارة.
- **الدفع** غير مربوط؛ الأسعار تحتاج دراسة تكلفة فعلية (تكلفة المادة ≈ بحث + تركيب بالنموذج القوي).
- التعرف على الصوت يعتمد على دعم المتصفح (Chrome/Safari/Edge).
- قاعدة SQLite مناسبة لخادم واحد؛ للتوسع الأفقي يُنقل الوصول في `db.ts` إلى PostgreSQL وتُنقل المهام الخلفية (`jobs.ts`) إلى طابور.

## 6. بنية المجلدات
```
manara/
├── server/
│   ├── index.ts            الخادم ومعالجة الأخطاء وتقديم الواجهة
│   ├── db.ts               مخطط قاعدة البيانات (وتوثيق ربطه بالكيانات المنطقية)
│   ├── auth.ts, limits.ts  الحسابات والجلسات، الاشتراكات والحدود
│   ├── ai/                 وحدات الذكاء الاصطناعي (انظر 2)
│   ├── services/           المنطق: الرحلات، المواد، المرافق، المصادر، التفضيلات، المهام الخلفية
│   └── routes/api.ts       الواجهة البرمجية مع التحقق من المدخلات (zod)
├── web/src/
│   ├── pages/              الترحيب، المقابلة والخطة، الرئيسية، المادة، الخريطة، المرافق، المكتبة، التقدم، المراجعة، الخطة، التفضيلات
│   ├── components/         مكونات الواجهة
│   ├── i18n.ts             النصوص العربية والإنجليزية
│   └── voice.ts            القراءة الصوتية والإملاء
└── tests/                  اختبارات الوحدات والتكامل
```
